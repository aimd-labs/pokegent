## Executive decision

Keep the current runtime. The upstream offers a useful small agent-facing API, named playthroughs, a basic Gen1 RAM reader and local navigation, a persistent Hermes driver, dashboard and developer examples. Pokegent adds the main missing FireRed implementation, strict ROM admission, atomic snapshots, typed options, verified single-writer execution, objectives, recovery, provider routing and robust run supervision. Recover useful **capabilities**, not legacy input authority. Priority remains FireRed reliability and the second-title seam in [#139](https://github.com/aimd-labs/pokegent/issues/139). No automatic upstream merge or rewrite.

## 2. Emulator and reader seams

### 2.1 PyBoy is not a working Pokegent game plugin yet

[Upstream emulator interface](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/emulator.py) is an abstract load/read/press/tick/save interface and two backends. [Current backend factory](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L1102-L1148) still chooses PyBoy on GB/GBC extension, but production [open_emulator](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/app.py#L1278-L1307) explicitly imports the FireRed profile loader and constructs PyGBAEmulator (mGBA implementation). [CLI info](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/cli.py#L406-L438) labels extension-derived family, not exact ROM support. Optional pyboy/pygba/autopilot extras in package metadata are not evidence of an installed, supported runner.

Three concrete PyBoy gaps, not an assumed need to replace the actor:
1. [Emulator base](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L325-L452) declares press_buttons and in-memory state methods that raise NotImplementedError by default. [PyBoy class](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L457-L578) implements single button/file state APIs but not those newer methods or explicit load_epoch.
2. [EmulatorActor](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L1286-L1348) defaults to GBA snapshot regions, though regions are configurable. [Snapshot and tap](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L1408-L1465) require coherent memory and bounded input/clock handling. Verify platform-specific address/region semantics and key release rather than reusing GBA memory ranges or assuming file saves satisfy actor contract.
3. [Actor save/load](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/emulator.py#L1617-L1656) calls in-memory backend serialization on the owner thread and atomically writes a state receipt. PyBoy needs equivalent validated bytes, monotonic host frame and restore epoch behavior and input cleanup. Don't bypass actor via legacy file APIs.

A small backend conformance suite should precede Gen1 reader work: load exact supported ROM, deterministic frame advance, single/chord hold semantics only when explicitly supported, release on exception/cancel, region bounds/atomic identity, save bytes/hash/restore validation, increasing restore epoch, no ROM writes, stale-frame refusal after load, shutdown and bounded failures. Public tests can use a fake backend; private native tests are separate. Follow existing [#139](https://github.com/aimd-labs/pokegent/issues/139) ordering.

### 2.2 Gen1 parser reuse is a candidate, not a port already done

[RedBlueMemoryReader](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/memory/red.py#L531-L796) has a concrete 44-byte party struct reader, internal species-index mapping, PP/PP-Up fields, big-endian Pokémon stats, single Special stat, BCD money, bag slots/terminator, basic battle enemy and flags/Dex counts. It clamps counts, maps unknown species to fallback labels and assumes a revision layout (module introduction mentions USA Rev-A). Its dialog active flag is joypad lock based; neither it nor the text-box value proves selectable input ownership. It does not establish verified PC storage/trade/doubles/full story, and Gen1 has different mechanics from Gen3 (not simply a smaller FireRed snapshot).

[GameMemoryReader](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/memory/reader.py) is a useful conceptual read surface, not a complete adapter. [State builder](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/state/builder.py#L19-L74) separately reads dictionary sections, catches failures and may return stack traces. Pokegent's [CompositeSnapshotSource](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/games/gen3/firered/reader/snapshot_sources.py) assembles typed same-boundary evidence; generic state builder still exists, but no proof it is the authoritative runtime source. Do not feed legacy partial dictionaries or traceback into decision models as trusted legality.

For a future Gen1 adapter:
- Start with one exact ROM/revision/language selected under [#139](https://github.com/aimd-labs/pokegent/issues/139); verify offsets, bank selection, text encoding, byte order, flags and memory ranges independently against pinned pret source and private local ROM; no filename inference. Distinguish Red, Blue, Yellow and Gold/Silver/Crystal.
- Keep generation semantics: 44-byte party vs box struct, internal species IDs vs national identity, DV/stat experience vs Gen3 IV/EV, type/stat differences and Gen1-specific battle effects. Facts absent/inapplicable must not become 0, fake abilities or invented fields. Validate raw lengths/counts and snapshots at transition boundaries; keep private trainer data local.
- Start with player/party/bag/map/flags, scene ownership and verified basic walk/menu; expand battle/PC/Dex/story separately. Port only independently reviewed generic MIT code and notices. No bulk copy of species/move/map/item names or decompilation tables.
- [Species tests](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/test_species_mapping.py) cover internal-to-Dex bijection, unknown IDs and mono/dual type rendering. [Collision tests](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/test_collision.py) cover dimensions/labels/tilesets; [movement script](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/test_movement.py) and [timing script](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/test_timing.py) use a private ROM. Use scenario patterns, not copied datasets or ROMs. Native full campaign remains unproven.

## 3. Navigation, overlay and player knowledge

[Upstream collision](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/collision.py#L87-L118) reads a 10×9 visible block grid using tileset collision data; it always marks E5 as walkable. This is useful for perception/visual debugging, not a complete dynamic world graph with current NPC occupancy, directional/ledge rules, warps or script gates. [A*](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/pathfinding.py) even assumes all neighbors walkable if no collision map is provided; do not reuse that fail-open behavior. Current [graph](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/navigation/graph.py) and [planner](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/navigation/planner.py) remain authoritative. #106 materialization stays paused pending operator direction.

[Overlay](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/overlay.py) adds an annotated viewport with stable labels and walkability tint. Consider a separate read-only visual diagnostic derived from the same admitted snapshot/frame identity, not a new navigation authority. Distinguish reachable / blocked / unknown and observed / guide-known; do not expose hidden items or unverified collision as truth. The current screenshot and stream contracts stay unchanged; an optional structured viewport/overlay could help external agents without requiring images for System One. Build one adapter-neutral projection after R05/R10, and test transition staleness and redaction.

## 4. Agent integration and session features

[Server](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/server.py#L557-L797) exposes a single global active session, named games, raw action sequences, save/load, narration and control. [Action parser](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/server.py#L230-L300) implements time-based button holds and a dialog loop. It does not require offered option identity/fresh scene revalidation. Upstream /action increments action counts and returns a later state rather than verified semantic postconditions. Do not reopen it or route raw action strings through a supposed compatibility facade.

Current [bridge](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/docs/server.md) has guarded frame/choice token, planning, fresh objective and interruption paths; queued HTTP 202 is **not** verified success. Existing observer dashboard and stream separate transport from authority. Optional Python SDK / MCP wrapper should be thin, provider-neutral, versioned and preserve frame identity and CAS. See [migration proposal](../../architecture/agent-session-integration.md). This is not a new API release or commitment to an MCP dependency.

[HermesDriver](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/autopilot.py#L127-L271) persists a Hermes session ID, polls control, sends screenshot/state and runs a subprocess each turn. Valuable: durable agent continuity and simple onboarding. Don't reuse its implicit raw-action authority, approval bypass flag, shared fixed temporary screenshot path, stdout-regex session discovery as sole authority, or retry without verifying game state. Current [owner review skill](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/skill/pokegent/SKILL.md) separates strategic owner from per-choice consumer; [owner lifecycle](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/ops/hermes/owner_status.py) checks exact persistent session and lease. Reuse these reviewed boundaries. Never require Hermes, start another controller, or bundle private profile memory.

[GameSessionManager](https://github.com/NousResearch/pokemon-agent/blob/f8a03e4a8bc58f1d9dda6d677a7436cc832a57a9/pokemon_agent/sessions.py) provides named playthroughs, an on-disk manifest, saves, objectives, agent-session ID and stats. Source risks to avoid: paths formed from supplied IDs/names, deletion via recursive removal without explicit containment at manager level, list summary chooses lexicographic latest while restore uses mtime, loading a session with no save can activate it on existing emulator state, rough badge count, display objectives are not RAM completion proof; single global mutable emulator can be switched without a demonstrated per-session transactional lease. These are source-level observations, not an executed exploit audit. Do not copy the manager as-is.

Current [StateWriter](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/app.py#L1310-L1436), [successor_state](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/live.py#L51-L88), [supervisor](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/supervisor.py#L345-L475) and [ledger](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/pokegent/ledger.py#L1-L112) are stronger foundations. Supervisor has one private LIVE_HOME, lock and segmented continuity; ledger tracks saves/runs/checkpoints/milestones but is a read/query/ingest record, not a playthrough manager. A named-playthrough layer is a genuine UX gap, not justification to duplicate these systems. Proposed manifest references existing local state and owner bindings; exact checkpoint identity and explicit switch lease; no mutable public dashboard or automatic rollback. Start read-only list/inspect and an explicit local CLI, then consider opt-in remote management only after separate security design.
