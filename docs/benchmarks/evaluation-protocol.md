## Evidence levels and gates

| Level | Dataset / execution | Pass evidence |
|---|---|---|
| L0 | public synthetic, mock provider, parser/fuzz, frozen fixtures | no unauthorized input, exact contract assertions; PR-head CI |
| L1 | sanitized frozen decision frames; labeled held-out families | acceptable-choice set, response identity/coverage, quality and cost; no input |
| L2a | optional pinned local battle simulator | exact rule cohort and seed/opponent, verified simulator result only |
| L2b | trusted private native state scenario | exact ROM, initial state digest, backend, frame/wall bounds, independent pre/post RAM proof |
| L3 | full cold-to-credits or explicitly declared resume campaign | badges/gates/Champion/Hall of Fame RAM and checkpoint lineage, no operator game intervention |
| L4 | postgame and ordinary capability coverage | title-specific complete acceptance matrix, not implied by L3 |

Public [CI](https://github.com/aimd-labs/pokegent/blob/c73774285e5e164d01629ca14a5e8e551e03493f/.github/workflows/ci.yml) has public-checks, native-helper and public-startup-latency. These are ROM-free; native-helper tests do not run real game. Keep public untrusted PR CI free of credentials and private ROM. Private native runs use reviewed immutable code, controlled environment, no automatic execution of fork changes, restricted secrets and artifacts. Exact baseline run success is historical, not new PR or campaign proof.

## Proposed reproducible manifest

See [JSON schema](scenario-manifest.schema.json) and [synthetic example](scenario-manifest.example.json). Schema is proposed, not runtime config. Store private ROM and checkpoint file paths outside git; manifest stores hashes and inert IDs, no paths or API keys. Use separate campaign/attempt/segment IDs and immutable source commit, release artifact digest, config/prompt/adapter hashes, host/backend, exact ROM and start hash (or synthetic fixture), mode, objective/required probes, knowledge policy, preparation type, seed lineage and budgets. Preserve same initial conditions across modes; if emulator RNG cannot be seeded through legal execution, use exact reviewed starting checkpoints and record deterministic input-derived seed lineage. Cold boot and prepared fixture cohorts cannot be pooled. Log provider identities, revisions and actual request attempts; missing evidence is null/explicit, not fabricated. Schema structural validation is not semantic or gameplay proof.

## Evaluation plan and denominators

1. Freeze test catalog and gold acceptable-action labels before tuning. Group by save/trajectory, scenario family, map/scene and near-duplicate input; no leakage between training/calibration/holdout. Multiple valid actions allowed; unknown cases excluded from labeled accuracy but counted in label coverage. Shadow proposal never has a counterfactual native outcome unless separately executed in isolated trial.
2. First complete #137 first-bad-transition synthetic replay for incidents #103, #110, #117, #119 and later #165/#178/#180/#181. Existing fixes don't replace permanent regression. Reproduce typed state/choice and exact rejection or result. Keep private trace-derived fixtures sanitized and independently authored. Fuzz malformed/oversized fields and stale frames; no hidden ROM contents.
3. Private native suite: exact setup and smoke, intro, walk/warp/forced movement, menu ownership/resume, battle/catch/switch/whiteout, fishing, Fly, goal success probes, save/restore and input cleanup; use R02/R03/R06/R08 proposed cases. Record every started scenario and refusal, not only successful reruns. A safe pause can be correct contract behavior but not campaign completion.
4. Campaign: compare agent, pure system1 and hybrid with paired starting identities/seeds where meaningful, fixed knowledge policy, objective and budget; preserve model/prompt versions, no silently changed defaults mid-cohort. Pure System One cannot invoke external agent; agent mode no System One; hybrid counts both. Any human input, RAM mutation, unplanned restore or operator objective rescue disqualifies unattended success; report assisted results separately.
5. Report all started attempts in completion denominator (including failed/timed out/censored), with separate infrastructure-invalid category and reason; never silently omit. Existing #135/#138 proposes >=90% main-story completion. Suggested staged sample plan: 3 pilot starts per mode for feasibility, then 10 matched independent starts per mode as screening, then a preregistered larger cohort for statistical claims. 9/10 is 90% observed, not proof true reliability >=90%; report Wilson/clustered intervals. No claim of meeting gate until reviewed exact evidence; count attempts, not segments or checkpoint reloads. No model-cost budget spent by this PR.

| Metric | Denominator / source |
|---|---|
| completion | independently verified unattended successes / all starts per cohort |
| choice quality | acceptable labeled proposals / labeled valid proposals, report coverage and invalid rate |
| verification | verified intended action / executed action-bearing choices, normal adverse game outcomes separate |
| progress | unique RAM-backed required milestone / logical decisions and wall/game-hour |
| latency | p50/p95 end-to-end, provider and handoff separately; count timeout separately |
| cost | actual HTTP attempts, usage and estimates/receipt incl failed starts; both model layers, missingness |
| safety/recovery | unauthorized inputs (0 required), stale/illegal rejection, stuck/recovery/wipes/rollback counts |
| compatibility | exact profile/backend/host, per capability implementation and verification independently |
